# بریف کامل برای ایجنت جدید — پروژهٔ نمره (Nomreh)

> این فایل را به‌عنوان پیام اول به ایجنت جدید بدهید. هر چیزی که برای ادامهٔ کار لازم است در آن هست.
> نسخه: ۲۰۲۶-۱۱-۰۵ · آخرین وضعیت تأییدشده: بیلد سالم، ۱۶۳ تست سبز، اتصال Provider برقرار **نیست**.

---

## ۱. نقش تو

تو ایجنتی هستی که باید یک مشکل شبکه‌ای را روی یک هاست واقعی (Plesk) حل کند و بعد پروژه را تا کارکرد کامل ببرد.
مخزن: `https://github.com/animocomics/animation` (عمومی) · شاخهٔ کاری: `arena/dfdcef22-animation`
اپ: «نمره» — پلتفرم فارسی تصحیح برگهٔ امتحان با هوش مصنوعی، Next.js 16.4.3 + React، RTL، Vazirmatn.

## ۲. صورت مسئله (یک جمله)

**سرور هیچ اتصال خروجی به اینترنت ندارد.** نه به Kaya، نه به GitHub، نه حتی به `1.1.1.1`. تا این حل نشود، هیچ مدل AI، هیچ کلید API و هیچ تغییری در کد کار نمی‌کند.

## ۳. شواهد قطعی (اینها اندازه‌گیری شده‌اند، حدس نیستند)

خروجی `npm run diagnose` روی خودِ هاست:

```
== 1. DNS configuration
  OK   nameservers: 185.192.112.100, 185.192.113.100      ← resolver واقعی هاستینگ، DNS سالم است

== 2. proxy / VPN artifacts
  OK   no TUN device                                        ← شکن/v2ray کل هاست را قبضه نکرده

== 4. raw-IP egress (no DNS)
  FAIL 1.1.1.1:443        ETIMEDOUT (5006ms)
  FAIL 1.1.1.1:80         ETIMEDOUT (5001ms)
  FAIL 8.8.8.8:53         ETIMEDOUT (5006ms)
  FAIL 213.176.6.243:443  ETIMEDOUT (5001ms)   ← Kaya
  FAIL 140.82.121.6:443   ETIMEDOUT (5004ms)   ← GitHub

== Kaya AI
  OK   system DNS: 213.176.6.243   ← آدرس درست حل می‌شود
  FAIL system 213.176.6.243:443    ETIMEDOUT

== verdict
  NOMREH_DIAGNOSE_FAILED
```

از پنل ادمین (`/admin` → «تشخیص شبکه»، نسخهٔ v9):

```
FAIL پروسهٔ VPN/DNS: 2 مورد در حال اجرا      ← این پیدا شده که خطای ابزار بود، پایین را بخوان
OK   کارت شبکهٔ تونل (TUN): هیچ
FAIL خروجی · port 1.1.1.1:443 · ETIMEDOUT
FAIL خروجی · port 1.1.1.1:80  · ETIMEDOUT
FAIL خروجی · port 8.8.8.8:53  · ETIMEDOUT
```

### چه چیزی را این شواهد رد می‌کند (دوباره وقت صرفش نکن)
- ❌ **DNS نیست.** نام‌ها درست حل می‌شوند.
- ❌ **IPv6 نیست.** `kayaai.ir` رکورد AAAA ندارد.
- ❌ **کلید API نیست.** درخواست حتی به مرحلهٔ TLS نمی‌رسد.
- ❌ **کد برنامه نیست.** همان کد روی شبکهٔ باز تست شده و request shape درست است.
- ❌ **Kaya/تحریم نیست.** چون `1.1.1.1` هم جواب نمی‌دهد.
- ❌ **`www.kayaai.ir`** هرگز وجود ندارد (`ENOTFOUND`) — آدرس را با `www` نساز.

### دو خطای ابزار که خودمان داشتیم و رفع شد (به آن‌ها استناد نکن)
1. «۲ پروسهٔ VPN در حال اجرا» **غلط بود**: پروسه‌های خودِ برنامه (`nomreh-vm/official/glibc` و worker نود) بودند و الگو مسیر `/official/` را گرفته بود. حالا فقط نام پروسه بررسی می‌شود.
2. «۱۰ پورت پروکسی باز» هم پورت‌های داخلی خودمان بود. حالا مستثنی شده.

## ۴. آنچه قبلاً کار می‌کرد و بعد از نصب ابزارها قطع شد

به گفتهٔ کاربر: **قبلاً Plesk از GitHub کلون می‌کرد و `pull` هم کار می‌کرد.** بعد از نصب v2ray/شکن، به یک‌باره هم GitHub و هم Kaya تایم‌اوت شدند.
خطای Plesk در همان دوره: `Failed connect to github.com:443; Connection timed out`.

## ۵. تنها سرنخ باقی‌ماندهٔ محلی

در همین صفحه، بخش «برنامهٔ رسمی شکن»، **یک محیط QEMU شکن در حال اجراست** (`در حال اجرا؛ AI در انتظار فعال‌سازی`).
یک QEMU با کارت شبکهٔ مجازی می‌تواند ترافیک هاست را از خودش عبور دهد؛ اگر آن محیط به اینترنت نرسد، نتیجه دقیقاً همین است: همهٔ پورت‌ها timeout.

**اولین کاری که باید بکنی:** محیط شکن را از پنل کامل «توقف» کن، بعد `npm run diagnose` بزن.
- اگر `1.1.1.1:443` سبز شد → مقصر QEMU بود، حل شد.
- اگر قرمز ماند → بسته‌ها از بالادست دور ریخته می‌شوند → مورد ۶.

## ۶. کارهایی که باید انجام بدهی (به همین ترتیب)

**گام ۰ — نصب آخرین بسته.** فایل `nomreh-deploy-2026-11-05-v9.zip` در ریشهٔ همان شاخه است. استخراج روی `/nomreh.arounidea.com`، بعد ری‌استارت، بعد Ctrl+F5. با `GET /api/admin/network-diagnostics` چک کن که `diagnosticsVersion` برابر `"v9"` باشد؛ اگر نبود، مرورگر نسخهٔ قدیمی را نشان می‌دهد.

**گام ۱ — خاموش‌کردن محیط شکن و اندازه‌گیری مجدد.** (مورد ۵)

**گام ۲ — اگر خروجی هنوز بسته بود: اثبات بیرونی.** از این سندباکس IP عمومی هاست را با یک سرویس بیرونی چک کن (مثلاً views/آی‌پی)، تا معلوم شود آدرس عمومی سرور عوض شده یا نه. اگر عوض شده، مشکل از لایهٔ سرویس‌دهنده است.

**گام ۳ — اسکالیشن به هاستینگ.** کاربر ترمینال ندارد (فقط کنسول npm در پنل). پس هر تغییری که root می‌خواهد (فایروال، `resolv.conf`، سرویس‌ها) **باید از هاستینگ درخواست شود**. متن آماده در بخش ۹.

**گام ۴ — بعد از باز شدن خروجی:** مسیر AI را تست کن. Kaya باید **مستقیم** برود (عمداً در `PROVIDER_HOSTNAMES` نیست، چون داخل ایران در دسترس است). با کلید واقعی `GET https://kayaai.ir/api/chat/completions` باید فهرست مدل‌ها را بدهد.

## ۷. قوانین سخت (نقض هرکدام = خرابی روی سایت زنده)

- 🔒 **هرگز رمز/کلید/توکن چاپ نکن** — نه در چت، نه در لاگ، نه در argv، نه در خروجی بیلد. هرگز از کاربر رمز نپرس.
- 🔒 پوشهٔ `/nomreh.arounidea.com` ریشهٔ اپ است، `../nomreh-data` دادهٔ کاربر است (**حذف نکن**)، `public` ریشهٔ وب، `server.js` فایل استارت.
- 🔒 **هر دو نسخهٔ asset لازم است**: `.next/static` (سرور بدون آن بالا نمی‌آید) **و** `public/_next` (nginx مرورگر را از آن سرو می‌کند). حذف هرکدام صفحهٔ ادمین را در «در حال آماده‌سازی» قفل می‌کند.
- 🔒 **`public/_next` قبل از `npm run build` باید حذف شود**، وگرنه بیلد با خطای `You can not have a '_next' folder inside of your public folder` می‌شکند.
- 🔒 **هاست Node 17 دارد.** بیلد/اجرا فقط با `npm run setup:plesk` / `npm run build:plesk` که Node 22 محلی می‌سازد. هرگز اپ را downgrade نکن.
- 🔒 **تغییر DNS کل هاست، Cloudflare، CageFS سراسری، کاربر جدید Plesk، رمز master — ممنوع.**
- 🔒 هیچ فایل زیپ داخل زیپ جدید نگذار (حجم دو برابر می‌شود).
- 🔒 هیچ‌وقت ادعای موفقیت بدون اندازه‌گیری واقعی نکن. اگر چیزی را ندیده‌ای، بگو ندیده‌ام.

## ۹. متن آمادهٔ تیکت هاستینگ

> با سلام،
> سرور من (دامنه `nomreh.arounidea.com`) هیچ اتصال **خروجی** به اینترنت ندارد. خروجی تست:
> `1.1.1.1:443` → timeout، `1.1.1.1:80` → timeout، `8.8.8.8:53` → timeout، `api.github.com:443` → timeout.
> سایت و اتصال ورودی سالم است، و DNS به resolverهای خودتان (`185.192.112.100`، `185.192.113.100`) وصل می‌شود.
> قبلاً همین سرور از GitHub کلون می‌کرد و اکنون نمی‌کند.
> لطفاً بررسی کنید: آیا فایروال/relay جلوی VPS ترافیک خروجی را drop می‌کند؟ آیا IP سرور در بلاک‌لیست است؟ آیا آدرس IP عمومی سرور تغییر کرده است؟

## ۱۱. نکتهٔ صادقانه برای شروع

اگر ایجنت جدید بلافاصله شروع کند به تغییر کد برای حل این مشکل، مسیر را اشتباه رفته است. اول باید **بیرون** باز شود، بعد تست واقعی.
