# نصب روی اکانت جدید Plesk + زیردامنهٔ جدید

نسخه: **v26** — `nomreh-direct-v26.zip` (۴۱٫۷ مگابایت)

این راهنما برای حالتی است که Node هاست فقط **17.9** است. لازم نیست چیزی روی هاست ارتقا پیدا کند.

---

## ۰) قبل از شروع — چه چیزی همراه بسته است

بستهٔ v26 آرشیو **Node 22 آماده** را داخل خودش دارد:

```
scripts/plesk-runtime/node-v22.22.3-linux-x64-glibc-217.tar.xz   (۳۱٫۴ مگابایت)
sha256 = 5de83ffe678e6c478b7be75708458c2a2f552c300c8a24fb4bdcd1574cb7e132
```

یعنی روی هاستِ Node 17.9 این اتفاق می‌افتد:

1. Plesk برنامه را با Node 17 اجرا می‌کند (`server.js`).
2. `server.js` می‌بیند نسخهٔ اصلی کمتر از ۲۲ است، پس خودش را دوباره با `scripts/plesk-node22.cjs` اجرا می‌کند.
3. آن اسکریپت آرشیوِ همراهِ بسته را **از روی هارد خودتان** باز می‌کند، sha256 را چک می‌کند و باینری `node v22.22.3` را در `../nomreh-data/runtime/node` می‌نشاند.
4. از آن لحظه، نصب، build و اجرای برنامه همه با Node 22 است.

هیچ چیزی از `github.com` یا `nodejs.org` گرفته نمی‌شود. اگر آرشیو همراه بسته نبود، اسکریپت سه mirror را امتحان می‌کرد و اگر همه بسته بودند شکست می‌خورد — وجود همان ۳۱ مگابایت دلیل کار کردن روی Node 17.9 است.

> بار اول `build:plesk` کمی طول می‌کشد (باز کردن آرشیو + تست باینری + build). پیشرفت در `../nomreh-data/build-progress.txt` نوشته می‌شود.

---

## ۱) زیردامنهٔ جدید را بساز

در Plesk → **Websites & Domains** → **Add Subdomain** (یا Add Domain):

| فیلد | مقدار |
|---|---|
| Subdomain | مثلاً `nomreh` |
| Domain | دامنهٔ خودتان |
| Document root | **همان ریشه‌ای که زیپ را باز می‌کنید** |

نتیجه: `https://nomreh.example.com`

**SSL:** از Plesk → **SSL/TLS Certificates** → *Install a free certificate (Let's Encrypt)* بگیرید. این کار اختیاری نیست: کوکی نشست `Secure` است و روی http ساده مرورگر آن را دور می‌ریزد و لاگین کار نمی‌کند.

در همین صفحه **Force HTTPS** را روشن کنید.

**PHP را لازم ندارید.** در تنظیمات دامنه، نوع اپلیکیشن را **Node.js** بگذارید.

---

## ۲) تنظیم Node.js روی زیردامنه

Plesk → دامنه → **Node.js**:

| فیلد | مقدار |
|---|---|
| Node.js version | **17** (هرچه هست — لازم نیست ۲۲ باشد) |
| Document root | ریشهٔ برنامه (همان‌جا که `server.js` هست) |
| Application Mode | `production` |
| Application root | ریشهٔ برنامه |
| Application startup file | **`server.js`** |

روی گزینه‌های `npm install` / `build` اگر Plesk پیشنهاد داد، **خارج شوید** — نصب از مسیر زیر انجام می‌شود، نه از دکمه‌های Plesk.

---

## ۳) بسته را آپلود و باز کن

1. زیپ را دانلود کنید (لینک در پیام؛ همان فایل روی برنچ است).
2. Plesk → **Files** → ریشهٔ زیردامنه → **Upload** → فایل `nomreh-direct-v26.zip`.
3. روی فایل راست‌کلیک → **Extract files** → روی فایل‌های موجود بازنویسی شود.

بعد از باز شدن باید این‌ها را ببینید: `server.js`، `package.json`، `app/`، `lib/`، `scripts/`، `.next/`، `.env.example`.

> `.next/` از قبل ساخته شده و همراه بسته است، پس اگر build روی هاست شکست بخورد هم سرویس با همین خروجی بالا می‌آید.

---

## ۴) فایل تنظیمات را بساز

در File Manager فایل `.env.example` را کپی کنید و نامش را **`.env.local`** بگذارید، بعد مقادیر را عوض کنید:

```
NOMREH_DATA_DIR=/var/www/vhosts/example.com/nomreh-data
NOMREH_SECRET_KEY=<خروجی openssl rand -base64 48>
NOMREH_ADMIN_USERNAME=admin
NOMREH_ADMIN_PASSWORD=<رمز قوی خودتان>
NOMREH_TEACHER_USERNAME=teacher
NOMREH_TEACHER_PASSWORD=<رمز قوی خودتان>
NOMREH_HIDE_DEMO_ACCOUNTS=1
PORT=3000
```

قواعدی که اگر رعایت نشوند دردسر می‌شود:

- `NOMREH_DATA_DIR` را **بیرون** از ریشهٔ برنامه بگذارید، وگرنه با هر آپلود بعدی ممکن است پاک شود. مسیر مطلق بدهید.
- `NOMREH_SECRET_KEY` را بعد از اولین اجرا **عوض نکنید** — کلید رمزنگاری کلید API ذخیره‌شده است و با عوض شدنش، کلید کایا خوانده نمی‌شود و باید دوباره وارد شود.
- `NOMREH_COOKIE_SECURE=0` را روی هاست **نگذارید**. آن فقط برای پیش‌نمایش بدون TLS است.
- `NOMREH_COOKIE_SAMESITE=none` را هم روی هاست **نگذارید**. آن مخصوص وقتی است که برنامه داخل iframe سایت دیگری نشان داده می‌شود. روی دامنهٔ خودتان همان `lax` درست است.
- رمزها فقط در همین فایل‌اند؛ در چت، لاگ یا گیت نگذارید.

`NOMREH_ADMIN_PASSWORD` و `NOMREH_TEACHER_PASSWORD` **فقط بار اول** که دیتابیس ساخته می‌شود استفاده می‌شوند. اگر بعداً عوضشان کنید، رمز ورود عوض نمی‌شود.

## ۵) نصب — فقط سه دستور

Plesk → دامنه → **Node.js** → **Run script** یا ترمینال (اگر دارید):

```
npm run setup:plesk
npm run build:plesk
npm run restart:plesk
```

| دستور | چه می‌کند | چقدر طول می‌کشد |
|---|---|---|
| `setup:plesk` | Node 22 را از آرشیو همراه بسته نصب می‌کند و وابستگی‌ها را نصب می‌کند | ۲ تا ۵ دقیقه (بار اول) |
| `build:plesk` | با همان Node 22 نسخهٔ اجرایی می‌سازد | ۱ تا ۳ دقیقه |
| `restart:plesk` | سرویس را بالا می‌آورد | چند ثانیه |

**هرگز `node -e` یا `node script.js` مستقیم اجرا نکنید** — روی Node 17 ممکن است وسط کار بشکند. همیشه از `npm run <script>` استفاده کنید، چون `npm` خودش `$npm_node_execpath` را درست ست می‌کند.

اگر فقط `.next` را عوض کردید (آپلود بعدی)، فقط `npm run restart:plesk` کافی است.

## ۶) بررسی سالم بودن نصب

```
npm run diagnose
```

بعد در مرورگر زیردامنه را باز کنید. باید صفحهٔ ورود بیاید.

**تست لاگین:** با `NOMREH_ADMIN_USERNAME` و رمز وارد شوید. اگر برگشت به همان صفحهٔ ورود:

1. `openssl s_client` لازم نیست؛ اول `https` بودن آدرس را چک کنید (اگر `http` باشد کوکی `Secure` دور ریخته می‌شود).
2. مطمئن شوید `NOMREH_COOKIE_SECURE=0` **نگذاشته‌اید**.
3. در Plesk لاگ برنامه را ببینید؛ اگر `303` به `/admin` می‌رود ولی برمی‌گردد، مشکل کوکی است نه رمز.

## ۷) اتصال به کایا

1. وارد پنل **مدیر** شوید.
2. کلید کایا را در بخش تنظیمات provider وارد و **ذخیره** کنید.
3. اول **ذخیره**، بعد **تست** — تست با کلیدِ ذخیره‌نشده خطای رمزگشایی می‌دهد.
4. دکمهٔ «آزمون واقعی سه‌لایه» را بزنید. یک درخواست واقعی می‌رود و جواب می‌آید یا لایهٔ شکست را می‌گوید.

**محدودیت مهم:** کل ماشین بیش از **۲۰۰ درخواست در ۲۰ دقیقه** ندارد و سقف درون برنامه **۱۲۰** است (`lib/server/outbound-window.ts`). این عدد را بالا نبرید و tester/watcher در حلقه نسازید — یک بار همین کار خروجی کل سرور را قطع کرد.

---

## ۸) تست آپلود (PDF و عکس)

1. یک آزمون بسازید و سؤال‌ها را تأیید کنید (تا تأیید نشود، تصحیح با خطای 409 رد می‌شود).
2. در صفحهٔ تصحیح، فایل را انتخاب کنید. هم `pdf` و هم `jpg/png/webp` قبول است.
3. PDF روی خود سرور رستر می‌شود (تا ۲۰ صفحه) و به‌صورت تصویر به مدل می‌رود؛ پس PDF اسکن‌شده هم کار می‌کند و متن قابل انتخاب لازم نیست.
4. نتیجه در همان آزمون ذخیره می‌شود.

اگر عکس آپلود می‌شود ولی تصحیح خطا می‌دهد، مشکل provider است نه آپلود.

## ۹) چیزهایی که روی این هاست ممنوع است

- تونل، relay، V2Ray، پروکسی، worker روی GitHub، یا هر دور زدنی. اتصال باید مستقیم باشد.
- `sudo`، `iptables`، دست‌کاری فایروال.
- `node -e` و اجرای مستقیم اسکریپت‌ها روی Node 17.
- بالا بردن سقف ۱۲۰/۲۰۰.
- گذاشتن رمز یا کلید در گیت، چت یا لاگ.

## ۱۰) اگر جایی گیر کرد

| نشانه | علت | کار |
|---|---|---|
| `Missing script: build:plesk` | زیپ قدیمی باز شده یا در ریشهٔ اشتباه | مطمئن شوید `package.json` در همان ریشه‌ای است که دستور را می‌زنید |
| `Nomreh requires its Node 22 runtime` | `setup:plesk` اجرا نشده یا آرشیو همراه بسته نیست | `npm run setup:plesk`؛ وجود `scripts/plesk-runtime/*.tar.xz` را چک کنید |
| `The Node runtime archive failed SHA-256` | آرشیو ناقص آپلود شده | زیپ را دوباره extract کنید |
| لاگین برمی‌گردد به `/login` | کوکی `Secure` روی http، یا `SAMESITE=none` روی دامنهٔ خودتان | https را روشن کنید و آن دو متغیر را بردارید |
| تصحیح خطای شبکه می‌دهد | خروجی هاست به کایا بسته است | `npm run kaya:check -- --once` و بعد `docs/kaya-block-diagnosis-fa.md` |
