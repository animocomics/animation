# نمره — پلتفرم چندکاربرهٔ تصحیح اوراق امتحانی

«نمره» یک محصول واقعی فارسی و RTL برای مدیریت کلاس، ساخت آزمون و بارم، خواندن عکس/PDF برگه با مدل چندوجهی، تطبیق هویت دانش‌آموز، ثبت نمره در کارنامه و تأیید نهایی توسط معلم است.

> **بدون OCR جداگانه:** تصویر و PDF مستقیم به مدل چندوجهی داده می‌شود. خروجی AI پیش‌نویس است؛ نمرهٔ نهایی با معلم است و دقت ۱۰۰٪ وعده داده نمی‌شود.

## امکانات نسخهٔ ۲

### حساب‌ها و مدیریت

- ورود واقعی با نام کاربری و رمز عبور و نشست `HttpOnly`
- نقش‌های `admin`، `teacher` و `reviewer`
- ساخت، فعال/غیرفعال‌سازی و تعیین رمز جدید کاربران توسط مدیر
- پیکربندی OpenAI، Gemini یا DeepSeek فقط توسط مدیر
- ذخیرهٔ API Key با `AES-256-GCM` روی سرور؛ عدم ارسال کلید یا حتی راهنمای کلید به معلم
- گزارش مصرف توکن، زمان پاسخ و رویدادهای ناموفق برای هر حساب، بدون نمایش محتوای برگه به مدیر

### کلاس، هویت و کارنامه

- کلاس‌های مستقل برای هر معلم با پایه، درس/رشته و سال تحصیلی
- فهرست دانش‌آموزان با ورود دستی، ویرایش، کد دانش‌آموزی و Import از CSV/TSV
- کد یکتای آزمون و اتصال هر آزمون به کلاس
- خواندن نام و کلاس از روی برگه توسط همان مدل چندوجهی
- نرمال‌سازی نام فارسی/عربی و تطبیق با فهرست کلاس
- تکمیل خودکار نام و کد فقط در تطبیق امن
- توقف انتساب خودکار در موارد زیر:
  - نام تکراری یا تطبیق مبهم؛
  - اطمینان پایین به هویت؛
  - ناسازگاری کلاس روی برگه با کلاس آزمون؛
  - تفاوت نام تشخیصی با انتساب قبلی؛
  - وجود برگهٔ دیگر برای همان دانش‌آموز.
- تأیید یا اصلاح انتساب توسط معلم در صف بازبینی
- ساخت ردیف خودکار کارنامه برای همهٔ اعضای کلاس
- هشدار واضح برای برگهٔ مفقود، نتیجهٔ مفقود، هویت مبهم و نمرهٔ نیازمند بازبینی
- گزارش جداگانهٔ هر آزمون و گزارش تجمیعی بین آزمون‌های یک کلاس
- خروجی CSV کارنامهٔ کلاس و نتایج آزمون، مناسب Excel فارسی

### موتور تصحیح

- Wizard چهارمرحله‌ای: مشخصات/کلاس، سؤال و بارم، برگه‌ها، کنترل و اجرا
- ۱۰ نوع سؤال: تستی، چندپاسخی، درست/غلط، جای‌خالی، پاسخ کوتاه، تشریحی، محاسباتی، شکل/نمودار، جورکردن و ترتیب‌دهی
- Rubric تفصیلی، پاسخ جایگزین، نمرهٔ جزئی و خطای انتقالی
- آپلود گروهی یا چند فایل برای یک دانش‌آموز و پیش‌نمایش برگهٔ اصلی
- اتصال سروری به:
  - OpenAI Responses API با Structured Outputs؛
  - Gemini GenerateContent با Response Schema؛
  - DeepSeek Responses API برای برگه‌های تصویری.
- رونوشت، شاهد/صفحه، نمرهٔ هر معیار، دلیل، اعتماد و هشدار
- محاسبهٔ مجدد و Clamp سروری نمره‌ها و تطبیق قطعی سؤال‌های تستی
- ممیزی دوم هدفمند در حالت متعادل/دقیق
- هشدار ناخوانایی، تصویر بی‌کیفیت، پاسخ مفقود، اعتماد پایین و مرز قبولی
- اجرای دو برگهٔ هم‌زمان، توقف، خطای مستقل و تلاش مجدد
- اصلاح نمره با حفظ مقدار اولیهٔ AI، تأیید/بازکردن مجدد و Audit Trail
- کارنامهٔ چاپی، JSON و CSV، تحلیل سؤال‌به‌سؤال و گزارش عملکرد کلاس

## اجرا

نیازمند Node.js 20 یا جدیدتر:

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. برای استفادهٔ واقعی تولیدی:

```bash
npm test
npm run typecheck
npm run build
npm start
```

### حساب‌های اولیهٔ نصب توسعه

در اولین اجرا، اگر پایگاه‌داده خالی باشد، این دو حساب ساخته می‌شوند:

| نقش | نام کاربری | رمز اولیه |
|---|---|---|
| مدیر سامانه | `admin` | `Admin@1405` |
| معلم نمونه | `teacher` | `Teacher@1405` |

روی صفحهٔ ورود، دکمه‌های پرکردن خودکار این حساب‌ها نیز در حالت پیش‌فرض نمایش داده می‌شوند.

**پیش از استقرار واقعی حتماً رمزهای اولیه را تغییر دهید یا حساب‌ها را با متغیرهای محیطی زیر پیش از اولین اجرا مقداردهی کنید.** پس از ساخته‌شدن کاربران، تغییر متغیر محیطی رمز فعلی را بازنویسی نمی‌کند.

### متغیرهای محیطی

نمونه در [`.env.example`](./.env.example) قرار دارد:

```bash
NOMREH_DATA_DIR=/absolute/path/to/persistent-data
NOMREH_SECRET_KEY='a-long-random-secret-for-provider-key-encryption'
NOMREH_ADMIN_USERNAME=admin
NOMREH_ADMIN_PASSWORD='replace-with-a-strong-password'
NOMREH_TEACHER_USERNAME=teacher
NOMREH_TEACHER_PASSWORD='replace-with-another-strong-password'
```

- `NOMREH_DATA_DIR`: محل پایگاه‌داده، فایل‌های برگه و کلید محلی رمزنگاری؛ پیش‌فرض `./data`.
- `NOMREH_SECRET_KEY`: راز رمزنگاری کلید Provider. در استقرار واقعی مقدار طولانی و تصادفی بدهید و در نسخهٔ پشتیبان امن نگه دارید. اگر تنظیم نشود، یک فایل راز با دسترسی محدود در data directory ساخته می‌شود.
- متغیرهای حساب فقط هنگام Seed اولین پایگاه‌داده استفاده می‌شوند.

### داده و پشتیبان‌گیری

```text
data/
  nomreh.db           # کاربران، نشست‌ها، فضای کاری‌ها، تنظیم رمزنگاری‌شده و مصرف
  uploads/<userId>/   # برگه‌های جدا شده برای هر کاربر
  .provider-secret   # فقط اگر NOMREH_SECRET_KEY تنظیم نشده باشد
```

از کل این فهرست و راز رمزنگاری نسخهٔ پشتیبان امن بگیرید. فهرست `data` در Git نادیده گرفته شده است.

> این نسخه برای یک نمونهٔ Node.js با دیسک پایدار و SQLite طراحی شده است. روی میزبان Serverless با فایل‌سیستم موقت یا چند نمونهٔ هم‌زمان بدون storage مشترک مستقر نکنید. مسیر مقیاس سازمانی در مسترپلن PostgreSQL، Object Storage و صف Worker است.

## مسیر استفادهٔ واقعی

1. با `admin` وارد شوید و در «مدیریت سامانه» Provider و مدل را انتخاب کنید.
2. کلید را وارد و «آزمایش و ذخیرهٔ امن» را بزنید؛ سپس حساب‌های معلم را بسازید.
3. با حساب معلم وارد شوید و در «کلاس‌ها» فهرست را دستی یا با CSV وارد کنید.
4. در «تصحیح جدید» عنوان، درس، کد یکتای آزمون و کلاس را انتخاب کنید.
5. برای هر سؤال، صورت، کلید و معیارهای مستقل با جمع نمرهٔ برابر وارد کنید.
6. عکس یا PDF برگه را بارگذاری کنید. ردیف اعضای کلاس از قبل ساخته شده و برگه‌های مفقود مشخص می‌مانند.
7. تصحیح را اجرا کنید. مدل نام و کلاس را از برگه می‌خواند و سامانه آن را با فهرست تطبیق می‌دهد.
8. در «بازبینی نمرات» ابتدا موارد هویت و سپس رونوشت، شواهد و نمره را کنترل و تأیید کنید.
9. گزارش آزمون را از «گزارش و تحلیل» و گزارش بین آزمون‌ها را از زبانهٔ «گزارش تجمیعی» کلاس بگیرید.

## امنیت و محدودیت‌ها

- رمز عبور با `scrypt` و نمک تصادفی ذخیره می‌شود؛ نشست با توکن تصادفی و Hash آن در SQLite نگه‌داری می‌شود.
- کوکی نشست `HttpOnly` و `SameSite=Lax` است و در Production با `Secure` ارسال می‌شود.
- مسیرهای Workspace، فایل، تصحیح، مدیریت کاربر و Provider احراز هویت و نقش را سمت سرور بررسی می‌کنند.
- هر کاربر فقط Workspace و فایل‌های خودش را می‌خواند یا تغییر می‌دهد. شناسهٔ آزمون نیز پیش از مصرف API بررسی می‌شود.
- ذخیرهٔ Workspace دارای Revision برای تشخیص نسخهٔ قدیمی است.
- کلید Provider در کد، آزمون، نتیجه، LocalStorage یا SessionStorage ذخیره نمی‌شود و در پاسخ به معلم قرار نمی‌گیرد.
- ارسال برگه به Provider مشمول سیاست نگهداری و پردازش دادهٔ همان سرویس است. برای دادهٔ واقعی از HTTPS و قرارداد/تنظیمات مناسب حریم خصوصی استفاده کنید.
- حجم هر فایل حداکثر ۱۵MB است. محدودیت مجموع هر درخواست تقریباً ۴۰MB برای OpenAI، ۱۴MB برای Gemini و ۲۴MB برای DeepSeek است.
- **DeepSeek در این نسخه PDF مستقیم نمی‌پذیرد.** برای DeepSeek صفحات را به JPG/PNG/WebP تبدیل کنید؛ PDF با OpenAI یا Gemini ارسال می‌شود.
- «اعتماد مدل» احتمال کالیبره‌شدهٔ درستی نیست. برای آزمون مهم، نمونه‌برداری انسانی و کالیبراسیون با نمره‌های معلم لازم است.
- اگر Provider یا کلید معتبر در دسترس نباشد، خطا نمایش داده می‌شود و نتیجهٔ ساختگی جایگزین تصحیح واقعی نمی‌شود.

### ارتقا از نسخهٔ ۱

دادهٔ متنی `LocalStorage` نسخهٔ ۱ در نخستین ورود هر کاربر به Workspace سرور همان حساب منتقل می‌شود. فایل‌های IndexedDB نسخهٔ قدیمی به سرور منتقل نمی‌شوند و باید دوباره بارگذاری شوند. کلید SessionStorage قدیمی حذف می‌شود و مدیر باید اتصال سراسری جدید را پیکربندی کند.

## ساختار مهم

```text
app/
  (workspace)/           # مسیرهای محافظت‌شده: داشبورد، کلاس، آزمون، بازبینی و گزارش
  login/                 # ورود واقعی
  api/auth/              # Login/Logout/Session
  api/admin/             # کاربران و مصرف، فقط مدیر
  api/provider/          # وضعیت و پیکربندی رمزنگاری‌شده
  api/files/             # فایل‌های تفکیک‌شدهٔ کاربر
  api/workspace/         # Workspace با Revision
  api/grade/             # ممیزی، نرمال‌سازی و ثبت مصرف
components/
  classes/               # فهرست، کارنامه و گزارش تجمیعی کلاس
  grading/               # Wizard، ویرایشگر سؤال و آپلود
  review/                # تصویر اصلی، هویت و صف بازبینی
  admin-panel.tsx        # مدیریت کاربر، Provider و مصرف
lib/
  server/auth.ts         # نشست و RBAC
  server/db.ts           # SQLite و Seed اولیه
  server/provider-config.ts # AES-GCM و وضعیت عمومی/مدیر
  server/providers.ts    # OpenAI / Gemini / DeepSeek
  roster.ts              # تطبیق هویت، CSV و ردیف‌های کارنامه
tests/                   # نمره، رمز عبور، هویت و فهرست کلاس
MASTER_PLAN.fa.md        # مسترپلن محصول، امنیت و پژوهش
```

## مسترپلن و پژوهش

مسترپلن کامل در [`MASTER_PLAN.fa.md`](./MASTER_PLAN.fa.md) قرار دارد و از صفحهٔ «راهنما» نیز قابل دانلود است. طراحی بر پایهٔ Rubric ریز، Evidence، جداسازی Rule Engine از مدل، عدم حدس در ناخوانایی، ارجاع محتاطانه و Human-in-the-loop انجام شده است.
