# نمره — پلتفرم چندکاربرهٔ تصحیح اوراق امتحانی

«نمره» یک محصول واقعی فارسی و RTL برای مدیریت کلاس، ساخت آزمون و بارم، خواندن عکس/PDF برگه با مدل چندوجهی، تطبیق هویت دانش‌آموز، ثبت نمره در کارنامه و تأیید نهایی توسط معلم است.

> **بدون OCR جداگانه:** تصویر مستقیم به مدل چندوجهی داده می‌شود. PDF برای OpenAI/Gemini مستقیم و برای DeepSeek، Z.AI GLM، MiniMax، Inkling-Small و Mistral Large 4 پس از تبدیل خودکار صفحات به تصویر، داخل خود سرور «نمره» ارسال می‌شود. خروجی AI پیش‌نویس است؛ نمرهٔ نهایی با معلم است و دقت ۱۰۰٪ وعده داده نمی‌شود.

## امکانات نسخهٔ ۲

### حساب‌ها و مدیریت

- ورود واقعی با نام کاربری و رمز عبور و نشست `HttpOnly`
- نقش‌های `admin`، `teacher` و `reviewer`
- ساخت، فعال/غیرفعال‌سازی و تعیین رمز جدید کاربران توسط مدیر
- پیکربندی OpenAI، Gemini، DeepSeek، Z.AI GLM، MiniMax، Inkling-Small یا Mistral Large 4 فقط توسط مدیر
- مسیر اختیاری شکن فقط برای APIهای هوش مصنوعی، با DNS مستقل از سیستم، لینک رمزنگاری‌شدهٔ اشتراک حرفه‌ای، آزمایش واقعی و کلید خاموش/روشن در مدیریت
- ذخیرهٔ API Key با `AES-256-GCM` روی سرور؛ عدم ارسال کلید یا حتی راهنمای کلید به معلم
- گزارش مصرف توکن، زمان پاسخ و رویدادهای ناموفق برای هر حساب، بدون نمایش محتوای برگه به مدیر

### کلاس، هویت و کارنامه

- کلاس‌های مستقل برای هر معلم با پایه، درس/رشته و سال تحصیلی
- فهرست دانش‌آموزان با ورود دستی، ویرایش، کد دانش‌آموزی و Import از CSV/TSV
- کد یکتای آزمون و اتصال هر آزمون به کلاس
- خواندن نام و کلاس از روی برگه توسط همان مدل چندوجهی
- نرمال‌سازی نام فارسی/عربی و تطبیق با فهرست کلاس
- تکمیل خودکار نام و کد فقط در تطبیق امن
- توقف انتساب خودکار در موارد زیر:
  - نام تکراری یا تطبیق مبهم؛
  - اطمینان پایین به هویت؛
  - ناسازگاری کلاس روی برگه با کلاس آزمون؛
  - تفاوت نام تشخیصی با انتساب قبلی؛
  - وجود برگهٔ دیگر برای همان دانش‌آموز.
- تأیید یا اصلاح انتساب توسط معلم در صف بازبینی
- ساخت ردیف خودکار کارنامه برای همهٔ اعضای کلاس
- هشدار واضح برای برگهٔ مفقود، نتیجهٔ مفقود، هویت مبهم و نمرهٔ نیازمند بازبینی
- گزارش جداگانهٔ هر آزمون و گزارش تجمیعی بین آزمون‌های یک کلاس
- خروجی CSV کارنامهٔ کلاس و نتایج آزمون، مناسب Excel فارسی

### موتور تصحیح

- Wizard چهارمرحله‌ای: مشخصات/کلاس، سؤال و بارم، برگه‌ها، کنترل و اجرا
- خواندن چند عکس/PDF سؤال و پاسخ‌نامهٔ معلم و ساخت پیش‌نویس قابل ویرایش؛ نقش هر فایل با دکمهٔ آپلود خودکار مشخص می‌شود و تأیید صریح معلم پیش از تصحیح الزامی است
- آپلود کاملاً جداگانهٔ عکس/PDF کلید، از جمله پاسخ‌نامهٔ تستی با گزینه‌های سیاه، پر، هاشور یا علامت‌گذاری‌شده؛ در حالت کلید جدا فقط پاسخ سؤال‌های موجود تغییر می‌کند و علامت مبهم یا چندگانه حدس زده نمی‌شود
- خواندن گزینهٔ سیاه/علامت‌خورده در برگهٔ دانش‌آموز و تطبیق قطعی شماره یا برچسب گزینه با همان سؤال؛ علامت چندگانه یا خارج از محدوده برای بازبینی متوقف می‌شود
- ۱۰ نوع سؤال: تستی، چندپاسخی، درست/غلط، جای‌خالی، پاسخ کوتاه، تشریحی، محاسباتی، شکل/نمودار، جورکردن و ترتیب‌دهی
- Rubric تفصیلی، پاسخ جایگزین، نمرهٔ جزئی و خطای انتقالی
- آپلود گروهی یا چند فایل برای یک دانش‌آموز و پیش‌نمایش برگهٔ اصلی
- پیش‌نمایش صفحه‌ای PDF با رندر امن سرور، بزرگ‌نمایی/چرخش و لینک بازکردن PDF اصلی؛ بدون وابستگی به افزونهٔ PDF مرورگر
- اتصال سروری به:
  - OpenAI Responses API با Structured Outputs؛
  - Gemini GenerateContent با Response Schema؛
  - DeepSeek Responses API برای تصویر و PDF با تبدیل خودکار صفحات به JPEG.
  - Z.AI GLM Chat Completions با مدل پیش‌فرض `glm-5.3-flash`، تصویر مستقیم و PDF با تبدیل خودکار صفحات به JPEG.
  - MiniMax Chat Completions با `MiniMax-M3.1-Flash` یا `MiniMax-M3`، Thinking جداشده و تصویر/PDF تبدیل‌شده؛
  - Inkling-Small روی Tinker با Messages API رسمی، تصویر PNG/JPEG با Base64 و Reasoning High؛ سرویس Serverless آن در وضعیت **Beta** است؛
  - Mistral Large 4 با `reasoning_effort: high`، JSON Mode و تصویر/PDF تبدیل‌شده؛ مدل در **Public Preview** است.
- رونوشت، شاهد/صفحه، نمرهٔ هر معیار، دلیل، اعتماد و هشدار
- محاسبهٔ مجدد و Clamp سروری نمره‌ها و تطبیق قطعی سؤال‌های تستی
- ممیزی دوم هدفمند در حالت متعادل/دقیق
- هشدار ناخوانایی، تصویر بی‌کیفیت، پاسخ مفقود، اعتماد پایین و مرز قبولی
- اجرای دو برگهٔ هم‌زمان، توقف، خطای مستقل و تلاش مجدد
- اصلاح نمره با حفظ مقدار اولیهٔ AI، تأیید/بازکردن مجدد و Audit Trail
- کارنامهٔ چاپی، JSON و CSV، تحلیل سؤال‌به‌سؤال و گزارش عملکرد کلاس

## اجرا

نیازمند Node.js 22 یا جدیدتر برای اجرای معمول:

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. برای استفادهٔ واقعی تولیدی:

```bash
npm test
npm run typecheck
npm run build
npm start
```

### Node اختصاصی و کاهش حجم Production در Plesk

در تنظیم **Build Command** همان اپ Node.js در Plesk، `npm run build:plesk` را قرار دهید. اگر Plesk فقط Node قدیمی مثل 17.9.1 داشته باشد، این دستور Node.js **22.22.3** مخصوص همان نمونه را در `NOMREH_DATA_DIR/runtime` نصب یا دوباره استفاده می‌کند؛ Node سایر دامنه‌ها و تنظیم سراسری هاست تغییر نمی‌کند. نصب وابستگی‌ها، Build، Prune و آزمایش SQLite/Canvas همگی با Node 22 انجام می‌شوند و `server.js` اجرای Production را به همان Runtime می‌سپارد.

باینری استاندارد با نسخهٔ ثابت و Lockfile از npm نصب می‌شود. برای Linux x64، اگر باینری استاندارد با glibc هاست ناسازگار باشد، راه‌انداز باینری همان نسخه از پروژهٔ Node.js unofficial-builds با الگوی `glibc-217` و **SHA-256 ثابت** را امتحان می‌کند. هیچ Runtime یا Header سراسری نصب نمی‌شود.

این دستور بعد از Build موفق، Cacheهای قابل‌ساخت و Dev Dependencies را حذف می‌کند؛ فایل‌های لازم برای اجرای Next، SQLite، رندر PDF و تصحیح باقی می‌مانند. وابستگی‌های Native با باینری ازپیش‌ساخته‌شده استفاده می‌شوند و Lifecycle Scripts هنگام نصب اپ غیرفعال‌اند.

- برای نصب فعلی که Build موفق دارد، اسکریپت `compact:plesk` همین پاک‌سازی را بدون Build مجدد انجام می‌دهد.
- TypeScript، Types و `pdf-lib` برای Buildهای بعدی حفظ می‌شوند؛ بنابراین Build مجدد به نصب خودکار ابزارهای اضافی نیاز ندارد.
- اسکریپت بدون وجود `BUILD_ID` متوقف می‌شود تا در صورت Build ناقص چیزی حذف نشود.
- `data/`، `NOMREH_DATA_DIR`، دیتابیس، Uploads، تنظیمات و فایل‌های کاربران هرگز پاک نمی‌شوند.
- برای توسعهٔ محلی یا نصب دوبارهٔ وابستگی‌ها، `npm ci` را اجرا کنید.

### حساب‌های اولیهٔ نصب توسعه

در اولین اجرا، اگر پایگاه‌داده خالی باشد، این دو حساب ساخته می‌شوند:

| نقش | نام کاربری | رمز اولیه |
|---|---|---|
| مدیر سامانه | `admin` | `Admin@1405` |
| معلم نمونه | `teacher` | `Teacher@1405` |

روی صفحهٔ ورود، دکمه‌های پرکردن خودکار این حساب‌ها نیز در حالت پیش‌فرض نمایش داده می‌شوند.

**پیش از استقرار واقعی حتماً رمزهای اولیه را تغییر دهید یا حساب‌ها را با متغیرهای محیطی زیر پیش از اولین اجرا مقداردهی کنید.** پس از ساخته‌شدن کاربران، تغییر متغیر محیطی رمز فعلی را بازنویسی نمی‌کند.

### متغیرهای محیطی

نمونه در [`.env.example`](./.env.example) قرار دارد:

```bash
NOMREH_DATA_DIR=/absolute/path/to/persistent-data
NOMREH_SECRET_KEY='a-long-random-secret-for-provider-key-encryption'
NOMREH_ADMIN_USERNAME=admin
NOMREH_ADMIN_PASSWORD='replace-with-a-strong-password'
NOMREH_TEACHER_USERNAME=teacher
NOMREH_TEACHER_PASSWORD='replace-with-another-strong-password'
```

- `NOMREH_DATA_DIR`: محل پایگاه‌داده، فایل‌های برگه و کلید محلی رمزنگاری؛ پیش‌فرض `./data`.
- `NOMREH_SECRET_KEY`: راز رمزنگاری کلید Provider و لینک به‌روزرسان شکن. در استقرار واقعی مقدار طولانی و تصادفی بدهید و در نسخهٔ پشتیبان امن نگه دارید. اگر تنظیم نشود، یک فایل راز با دسترسی محدود در data directory ساخته می‌شود.
- متغیرهای حساب فقط هنگام Seed اولین پایگاه‌داده استفاده می‌شوند.

### داده و پشتیبان‌گیری

```text
data/
  nomreh.db           # کاربران، نشست‌ها، فضای کاری‌ها، تنظیم رمزنگاری‌شده و مصرف
  uploads/<userId>/   # برگه‌های جدا شده برای هر کاربر
  .provider-secret   # فقط اگر NOMREH_SECRET_KEY تنظیم نشده باشد
```

از کل این فهرست و راز رمزنگاری نسخهٔ پشتیبان امن بگیرید. فهرست `data` در Git نادیده گرفته شده است.

> اجرای Production فقط روی Node.js و هاست خودت انجام می‌شود؛ داده‌ها در SQLite و فایل‌های برگه روی دیسک پایدار همان هاست باقی می‌مانند.

## اتصال اختیاری AI از مسیر شکن

شکن در این یکپارچه‌سازی به‌عنوان **سرویس DNS** استفاده می‌شود، نه پروکسی HTTP/SOCKS با نام کاربری و رمز. «نمره» هیچ‌وقت DNS سیستم‌عامل، Plesk، مرورگر معلم یا ترافیک عمومی سایت را تغییر نمی‌دهد. فقط Resolver اختصاصی درخواست‌های سرور به دامنه‌های Provider، آدرس را از DNS انتخاب‌شده می‌گیرد و TLS همچنان با نام اصلی دامنهٔ Provider برقرار می‌شود.

1. وارد «مدیریت سامانه ← اتصال هوش مصنوعی» شوید و در بخش «مسیر اختصاصی API با شکن» نوع رایگان یا حرفه‌ای را انتخاب کنید.
2. DNS رسمی به‌صورت خودکار پر می‌شود: رایگان `178.22.122.100` و `185.51.200.2`؛ حرفه‌ای `178.22.122.101` و `185.51.200.1`. در صورت تغییر رسمی آدرس‌ها، بخش «نمایش یا ویرایش DNS» قابل ویرایش است.
3. برای شکن حرفه‌ای، «لینک به‌روزرسان» را از «پنل شکن ← سفارش ← اطلاعات سرویس» کپی و در فیلد اختصاصی قرار دهید. این لینک برای ثبت IP سرور است، محرمانه محسوب می‌شود و با همان راز `AES-256-GCM` رمزنگاری می‌شود. رمز حساب شکن در «نمره» لازم نیست. فراخوانی هنگام اتصال و هر ۶ ساعت در صورت فعال‌بودن انجام می‌شود تا IP جدید هم ثبت شود.
4. «آزمایش، ذخیره و فعال‌سازی» را بزنید. مطابق ترتیب راهنمای رسمی، ابتدا Resolver اختصاصی همان DNS حرفه‌ای برای لینک به‌روزرسان به کار می‌رود. در صورت خطای انتقال، روش مستقل HTTPS در Node نیز با همان Resolver بررسی می‌شود. پس از ثبت موفق IP، برنامه حدود یک دقیقه صبر می‌کند و سپس DNS و پاسخ واقعی Google Gemini را بررسی می‌کند. تست بدون API Key است و پاسخ «کلید لازم/نامعتبر» از Endpoint گوگل نشان می‌دهد مسیر شبکه به API رسیده است؛ صحت کلید و مدل باید جداگانه با «آزمایش اتصال» Provider بررسی شود.
5. در صورت خطا، شکن فعال نمی‌شود و پیام مرحلهٔ خطا نمایش داده می‌شود. «غیرفعال‌کردن شکن» بلافاصله رفتار مستقیم Provider را برمی‌گرداند.

در حالت فعال، خطای DNS یا اتصال شکن به‌صورت پنهان به مسیر مستقیم Fallback نمی‌شود تا مدیر وضعیت واقعی را بداند. برای کارکرد این مسیر، هاست باید اجازهٔ DNS خروجی به سرور انتخاب‌شده و HTTPS خروجی به شکن/Provider را بدهد. پشتیبانی دامنه و وضعیت سرویس را از [سایت رسمی شکن](https://shecan.ir/) و [راهنمای رسمی اشتراک حرفه‌ای](https://shecan.ir/tutorials/tutorials-pro/) بررسی کنید؛ اجرای تست محلی یا موفقیت با Mock به معنی تضمین دسترسی واقعی نیست.

## استقرار روی Plesk

این نسخه برای اجرا روی ساب‌دامین `nomreh.arounidea.com` و از مخزن خصوصی GitHub آماده است. Plesk با **Remote repository** و HTTPS/Fine-grained Token فقط از شاخهٔ `arena/f4b832aa-animation` Pull می‌کند و Webhook همان مخزن، Pull و Deployment خودکار را انجام می‌دهد. Workflow قدیمی GitHub Actions برای این مسیر لازم نیست و باید غیرفعال بماند تا دو Deploy هم‌زمان انجام نشود.

تنظیم اپ Node.js همان ساب‌دامین:

- **Application Root:** همان Deployment directory، یعنی `/nomreh.arounidea.com`؛
- **Document Root:** `/nomreh.arounidea.com/public`؛
- **Application Startup File:** `server.js`؛
- **Application Mode:** `production` و Package Manager برابر `npm`؛
- **NOMREH_DATA_DIR:** مقدار پیشنهادی `../nomreh-data`، بیرون از Document Root و Deployment directory؛
- رمزهای امنیتی فقط در Environment همان اپ و بدون ارسال به Git نگهداری شوند.

پس از Pull، یک بار `npm run build:plesk` را از **Run Node.js commands / Run script** اجرا کنید و بعد از موفقیت، **Enable Node.js / Restart App** را بزنید. NPM Install جداگانه لازم نیست. برای Build و Restart خودکار در Deploymentهای بعدی، Post-deployment actions را فقط با این دستورها تنظیم کنید:

```sh
npm run build:plesk
mkdir -p tmp
touch tmp/restart.txt
```

فهرست داده و راز رمزنگاری را در Backup هاست نگه دارید. `runtime/` داخل فهرست داده قابل بازسازی است و Build هیچ دیتابیس، Upload یا Workspaceای را پاک نمی‌کند. هیچ سرویس ابری یا پیکربندی جداگانه‌ای لازم نیست.

## مسیر استفادهٔ واقعی

1. با `admin` وارد شوید و در «مدیریت سامانه» Provider و مدل را انتخاب کنید.
2. کلید را وارد و «آزمایش و ذخیرهٔ امن» را بزنید؛ سپس حساب‌های معلم را بسازید.
3. با حساب معلم وارد شوید و در «کلاس‌ها» فهرست را دستی یا با CSV وارد کنید.
4. در «آزمون جدید» عنوان، درس، کد یکتای آزمون و کلاس را انتخاب کنید.
5. در گام ۲ سؤال و کلید را دستی وارد کنید یا با دکمه‌های جداگانه چند JPG/PNG/WebP/PDF سؤال و پاسخ‌نامهٔ معلم را بارگذاری کنید. برای کلید مستقل، «افزودن عکس/PDF کلید» را بزنید؛ اگر فقط فایل کلید وجود داشته باشد، حالت «کلید جدا» خودکار فعال می‌شود و فقط پاسخ سؤال‌های موجود به‌روزرسانی می‌شود. پاسخ‌نامهٔ تستی با گزینه‌های سیاه/علامت‌خورده هم خوانده می‌شود، اما علامت مبهم یا چندگانه متوقف و نمایش داده می‌شود. پیش‌نویس را با برگهٔ اصلی مقایسه و ویرایش کنید؛ سپس «تأیید سؤال‌ها و کلید» را بزنید.
6. عکس یا PDF برگهٔ دانش‌آموز را بارگذاری کنید؛ چند صفحهٔ یک نفر در کارت همان دانش‌آموز قرار می‌گیرد. ردیف اعضای کلاس از قبل ساخته شده و برگه‌های مفقود مشخص می‌مانند.
7. تصحیح را اجرا کنید. مدل نام و کلاس را از برگه می‌خواند و سامانه آن را با فهرست تطبیق می‌دهد.
8. در «بازبینی نمرات» ابتدا موارد هویت و سپس رونوشت، شواهد و نمره را کنترل و تأیید کنید.
9. گزارش آزمون را از «گزارش و تحلیل» و گزارش بین آزمون‌ها را از زبانهٔ «گزارش تجمیعی» کلاس بگیرید.

## امنیت و محدودیت‌ها

- رمز عبور با `scrypt` و نمک تصادفی ذخیره می‌شود؛ نشست با توکن تصادفی و Hash آن در SQLite نگه‌داری می‌شود.
- کوکی نشست `HttpOnly` و `SameSite=Lax` است و در Production با `Secure` ارسال می‌شود.
- مسیرهای Workspace، فایل، تصحیح، مدیریت کاربر، Provider و شکن احراز هویت و نقش را سمت سرور بررسی می‌کنند؛ وضعیت و لینک اشتراک شکن فقط در مسیر Admin است.
- هر کاربر فقط Workspace و فایل‌های خودش را می‌خواند یا تغییر می‌دهد. شناسهٔ آزمون نیز پیش از مصرف API بررسی می‌شود.
- ذخیرهٔ Workspace دارای Revision برای تشخیص نسخهٔ قدیمی است.
- کلید Provider در کد، آزمون، نتیجه، LocalStorage یا SessionStorage ذخیره نمی‌شود و در پاسخ به معلم قرار نمی‌گیرد.
- ارسال برگه به Provider مشمول سیاست نگهداری و پردازش دادهٔ همان سرویس است. برای دادهٔ واقعی از HTTPS و قرارداد/تنظیمات مناسب حریم خصوصی استفاده کنید.
- حجم هر فایل ذخیره‌شده حداکثر **۱۰۰ مگابایت (۱۰۰MiB)** است؛ این سقف در آپلود سرور، بررسی مرورگر و Schema اعمال می‌شود. محدودیت مجموع هر درخواست مدل جدا است و تقریباً ۴۰MB برای OpenAI، ۱۴MB برای Gemini و ۲۴MB برای DeepSeek، Z.AI GLM، MiniMax، Inkling و Mistral است. فایل ۱۰۰ مگابایتی بدون کنترل به Provider ارسال نمی‌شود؛ حجم پیش و پس از تبدیل بررسی می‌شود.
- **PDF برای هر هفت Provider پشتیبانی می‌شود.** در تصحیح، OpenAI و Gemini معمولاً فایل را مستقیم دریافت می‌کنند و برای DeepSeek، Z.AI GLM، MiniMax، Inkling-Small و Mistral Large 4 صفحات با Renderer داخلی و بدون سرویس خارجی به JPEG باکیفیت تبدیل می‌شوند. در خواندن سؤال/کلید یا پرهیز از سقف حجم، تبدیل PDF به تصویر صفحه انجام می‌شود و PDF اصلی برای پیش‌نمایش حفظ می‌شود. هر PDF تا ۲۰ صفحه و هر تصحیح یا خواندن سؤال/کلید تا ۳۰ صفحه/فایل پشتیبانی می‌شود. PDF رمزدار یا خراب باید دوباره و بدون رمز بارگذاری شود.
- «اعتماد مدل» احتمال کالیبره‌شدهٔ درستی نیست. برای آزمون مهم، نمونه‌برداری انسانی و کالیبراسیون با نمره‌های معلم لازم است.
- اگر Provider یا کلید معتبر در دسترس نباشد، خطا نمایش داده می‌شود و نتیجهٔ ساختگی جایگزین تصحیح واقعی نمی‌شود.

### ارتقا از نسخهٔ ۱

دادهٔ متنی `LocalStorage` نسخهٔ ۱ در نخستین ورود هر کاربر به Workspace سرور همان حساب منتقل می‌شود. فایل‌های IndexedDB نسخهٔ قدیمی به سرور منتقل نمی‌شوند و باید دوباره بارگذاری شوند. کلید SessionStorage قدیمی حذف می‌شود و مدیر باید اتصال سراسری جدید را پیکربندی کند.
